## 1. 安装方法

### 1.1 Chrome / Edge 浏览器

1. 打开浏览器，访问 `chrome://extensions/`（Chrome）或 `edge://extensions/`（Edge）
2. 开启右上角的"开发者模式"
3. 点击"加载已解压的扩展程序"
4. 选择本项目的根目录（包含 `manifest.json` 的文件夹）
5. 扩展图标将出现在浏览器工具栏中

### 1.2 验证安装

点击浏览器工具栏中的 🛡️ 图标，应弹出设置面板，显示"未配置 API"状态。

## 2. 配置教程

### 2.1 获取 API Key

#### DeepSeek（推荐国内用户）
1. 访问 [DeepSeek 开放平台](https://platform.deepseek.com/)
2. 注册/登录账号（支持国内手机号）
3. 进入"API Keys"页面，点击"创建 API Key"
4. 复制以 `sk-` 开头的 Key

#### Kimi / Moonshot（推荐国内用户）
1. 访问 [Moonshot AI 开放平台](https://platform.moonshot.cn/)
2. 注册/登录账号（支持国内手机号）
3. 进入"API Key 管理"，创建新 Key
4. 复制 Key

#### OpenAI
1. 访问 [OpenAI Platform](https://platform.openai.com/)
2. 注册/登录账号
3. 进入 API Keys 页面，创建新 Key
4. 复制以 `sk-` 开头的 Key

#### Claude (Anthropic)
1. 访问 [Anthropic Console](https://console.anthropic.com/)
2. 注册/登录账号
3. 进入 API Keys 页面，创建新 Key
4. 复制 Key

> ⚠️ **安全提示**：API Key 相当于您的账号密码，请勿分享给他人。本扩展仅将 Key 存储在您的浏览器本地。

### 2.2 配置扩展

1. 点击浏览器工具栏中的 🛡️ 图标，点击"详细设置"
2. 在"API 设置"标签页中：
   - 选择您的 AI 提供商（OpenAI / Claude / 自定义）
   - 粘贴 API Key
   - 选择模型（推荐使用 GPT-4o Mini 或 Claude 3 Haiku，性价比高）
3. （可选）在"风格与类型"标签页中调整反驳风格和检测类型
4. 点击"保存设置"

## 3. 使用流程

### 3.1 生成反驳

1. **浏览知乎**：打开任意知乎问题页面
2. **发现问题**：当您看到包含错误的回答时
3. **点击按钮**：在回答下方的操作栏中，点击"🛡️ 生成反驳"按钮
4. **等待分析**：扩展会自动提取回答内容并发送给 AI 分析（通常 3-10 秒）
5. **查看分析**：弹出错误分析面板，显示：
   - 检测到的错误类型（事实错误、逻辑谬误等）
   - 置信度标识（高 / 中 / 低）
   - 错误详情卡片（原文陈述与纠正信息）
   - 分析摘要
   - 生成的反驳预览，可点击 📋 复制到剪贴板
   - 按住标题栏可拖动面板到其他位置
   - 按 `Esc` 或点击右上角 ✕ 按钮可关闭面板
   
   关闭面板后，再次点击同一回答下的“🛡️ 生成反驳”按钮，会直接恢复上次的面板状态，不会重新生成。点击“使用此反驳”后，该缓存会被清除。
6. **反馈（可选）**：如果生成结果有用，可点击主操作区左侧的「👍 有用」；如果想指出问题，可展开「✏️ 优化这次生成」，点击快捷标签（漏重点 / 太泛泛 / 不准确 / 语气差），系统会记录您的反馈并在重新生成时参考
7. **使用反驳**：点击"使用此反驳"，生成的内容将自动填入评论框
8. **重新生成（可选）**：如果对生成结果不满意，可点击“🔄 重新生成”，AI 会根据您的反馈换一个角度重新生成反驳内容。您也可以先点击反驳预览下方的「✏️ 优化这次生成」，输入具体要求（如“请更简短一些”“重点反驳数据造假部分”），或点击快捷反馈标签，再点击“🔄 重新生成”。
   - 系统会自动整理您多次输入的自定义要求，提炼出“💡 我理解你的要求”摘要（如“自然、简短、像真人说话”），并据此重新生成。
   - 如果系统理解有偏差，您可以点击摘要旁的“修改”按钮手动编辑核心意图。
   - AI 会结合核心意图重新生成，并在结果中提示“已按‘xxx’重新生成”。不同风格的自定义要求相互独立，方便对比。
9. **审核修改**：在评论框中查看、修改生成的内容
10. **发布评论**：确认无误后，点击知乎的“发布”按钮

### 3.2 如果未检测到错误

如果 AI 认为该回答没有明显错误，分析面板会提示"未检测到明显错误"。此时您可以：
- 尝试手动指出问题
- 检查是否遗漏了某些错误类型（在设置中启用更多类型）
- 直接关闭面板，不生成反驳

### 3.3 如果自动填充失败

如果扩展未能自动将内容填入评论框：
- 反驳内容会自动复制到您的剪贴板
- 手动点击评论按钮，粘贴内容即可

## 4. 设置详解

### 4.1 API 设置

| 选项 | 说明 | 建议 |
|------|------|------|
| AI 提供商 | 选择使用哪家 AI 服务 | 国内用户推荐 DeepSeek 或 Kimi |
| API Key | 您的 API 密钥 | 妥善保管，不要泄露 |
| API Base URL | 自定义 API 地址（可省略 https://） | 仅自定义 API 需要填写；保存时浏览器会弹窗请求访问该域名，需点击「允许」 |
| 模型 | AI 模型版本 | 推荐 deepseek-v4-pro 或 kimi-k2.6 |
| Temperature | 生成随机性 | 0.7 适合大多数场景 |
| Max Tokens | 最大生成长度 | 2048 足够生成详细反驳 |

> **关于域名授权**：内置提供商（DeepSeek / Kimi / OpenAI / Claude）的域名已随扩展安装一并授权，无需额外操作；
> 自定义 API 的域名只能在保存配置时按需申请。如果在授权弹窗中点了「拒绝」，配置**不会**被保存，
> 请重新点击保存并选择「允许」。本地模型地址（`localhost` / `127.0.0.1`，如 Ollama）同样需要授权。

#### 使用 OpenCode Go / Zen（可选）

如果你订阅了 OpenCode Go（或使用 Zen），可以把它当作自定义 API 接入：

| 项 | 填写内容 |
|----|----------|
| AI 提供商 | 自定义 API |
| API Base URL | `https://opencode.ai/zen/go/v1` |
| 模型 | 需选择走 `/chat/completions` 的模型，例如 `kimi-k2.6`、`kimi-k2.7-code`、`glm-5.3`、`glm-5.3-flash`、`deepseek-v4.1-flash`、`longcat-2.0` |
| API Key | 在 OpenCode Console 复制的 Key |

扩展会自动附带网关要求的 `x-opencode-session`（按当前回答派生；同一回答的重新生成、切换风格会复用同一标识），
无需手动配置。保存时浏览器仍会请求访问 `opencode.ai` 的授权。

> ⚠️ OpenCode 官方文档说明 Go **面向 OpenCode 及产生同类流量的编码代理**，并会监控异常流量。
> 本扩展的用途（生成知乎反驳评论）不在其文档描述的范围内，请自行评估账号风险；
> 对稳定性要求高的场景建议使用内置的 DeepSeek / Kimi 直连。

### 4.2 反驳风格

| 风格 | 适用场景 | 特点 |
|------|----------|------|
| 温和理性 | 一般讨论 | 平和、建设性，易于接受 |
| 直接犀利 | 明显错误 | 观点鲜明，有力但不攻击 |
| 学术严谨 | 专业话题 | 引用规范，术语准确 |
| 自然真实 | 避免 AI 痕迹 | 口语化、带情绪，像真人随手评论 |

### 4.3 错误类型

您可以选择让 AI 重点检测哪些类型的错误：

- **事实错误**：与公认事实相悖
- **逻辑谬误**：论证过程存在逻辑问题
- **历史虚无主义**：歪曲历史
- **数据造假**：编造或误用数据
- **科学错误**：违背科学原理
- **论证不完整**：回答遗漏了关键原因、视角或必要条件

建议保持全部启用，以获得最全面的分析。

### 4.4 功能开关

- **显示错误分析**：生成前显示分析面板（建议开启）
- **自动填充评论框**：自动将内容填入输入框（建议开启）
- **要求标注来源**：让 AI 为关键事实提供依据，并以真人措辞表达（如"之前新闻都报过"），不会出现"公开报道显示"这类报道腔（建议开启）
- **启用历史记录**：保存生成记录（建议开启）
- **补充遗漏视角**：对原因分析类问题，自动检查并补充被忽略的关键论点（建议开启）

### 4.5 完整性检查严格程度

调整 AI 对「论证不完整」的敏感程度：
- **宽松**：仅在明显遗漏时指出
- **标准**：正常检查遗漏的关键论点（默认）
- **严格**：主动挖掘被忽略的深层原因

### 4.6 高级：自定义 Prompt 后缀

在系统 Prompt 末尾追加您自己的规则。例如：
> 对历史话题，必须同时考虑政治、经济、军事三个维度。

留空则不追加任何内容。

## 5. 常见问题

### Q1：为什么按钮没有出现在回答下方？

可能原因：
- 知乎页面结构更新，扩展需要适配
- 回答区域尚未完全加载（知乎使用懒加载）
- 扩展未正确安装

解决方法：
- 刷新页面后等待 2-3 秒
- 滚动页面触发内容加载
- 检查扩展是否已启用

### Q2：点击按钮后一直显示"生成中"？

可能原因：
- API Key 配置错误或余额不足
- 网络连接问题
- 知乎内容提取失败

解决方法：
- 检查 API Key 是否正确
- 检查 API 账户余额
- 查看浏览器控制台（F12 → Console）获取详细错误

### Q3：生成的反驳不准确或不全面怎么办？

- AI 分析可能存在偏差，**请务必人工审核**
- 点击"重新生成"按钮，让 AI 换一个角度重新生成
- 展开「✏️ 优化这次生成」后点击快捷反馈标签（如"漏重点"、"太泛泛"、"不准确"），系统会记录您的意见并在重新生成时重点改进
- 在设置中开启"补充遗漏视角"，让 AI 自动检查关键论点是否遗漏
- 调整"完整性检查严格程度"，提高对论证不完整的敏感度
- 可在设置中调整 Temperature 值（降低可使输出更确定）
- 更换更强的模型（如 DeepSeek V4 Pro、GPT-5.5 或 Claude 4 Sonnet）
- 手动修改生成的内容

### Q4：会泄露我的隐私吗？

不会：
- API Key 仅存储在您的浏览器本地
- 回答内容直接发送给您配置的 AI 服务商
- 不经过任何第三方中转服务器
- 不上传您的个人信息

### Q5：使用这个工具会被知乎封号吗？

本工具的设计理念是**辅助而非替代**人工：
- 不自动发布任何内容
- 所有评论必须经您审核后手动发布
- 不批量操作、不刷屏
- 合理使用不会触发风控

但仍需注意：
- 避免频繁使用（短时间内多次生成）
- 发布内容需遵守知乎社区规范
- 对生成内容的真实性负责

## 6. 故障排除

### 查看错误日志

1. 在知乎页面按 `F12` 打开开发者工具
2. 切换到 Console（控制台）标签
3. 查找以 `[知乎反驳助手]` 开头的日志

### 重置配置

如果设置出现问题，可以重置为默认值：
1. 打开扩展设置页面
2. 在浏览器控制台执行：
   ```javascript
   chrome.storage.local.remove('zhihu_remark_config')
   ```
3. 刷新设置页面
