# Chrome 扩展多平台营销与审核填写手册

> 本文档汇总了「知乎反驳助手」在 Chrome Web Store、Product Hunt、X.com、知乎四个平台的审核文案与营销策略，供后续同类 Chrome 扩展产品参考复用。

---

## 一、Chrome Web Store 审核填写（隐私权规范）

### 单一用途说明

```
本扩展的唯一用途是在知乎（zhihu.com）页面中为包含事实错误、逻辑谬误、历史歪曲等问题的回答，提供一键生成有理有据的反驳评论草稿的功能。所有生成内容均需用户人工审核后方可发布，扩展不执行任何自动发布、批量操作或数据爬取行为。
```

### 需使用远程代码的理由

```
本扩展不使用任何远程代码。所有 JavaScript 代码均已打包在扩展包内，通过 Manifest V3 的 service worker 和 content scripts 本地运行。扩展仅通过浏览器原生的 fetch API 向用户自行配置的 AI 服务商（如 DeepSeek、OpenAI 等）发送 HTTPS 请求，不存在从远程服务器下载或执行代码的行为。
```

### 需使用主机权限的理由

**知乎域名：**
> 扩展需要在知乎问答和专栏页面中注入"生成反驳"按钮，并提取回答/文章的标题、正文、作者等信息以供 AI 分析。主机权限仅用于内容脚本（content script）在匹配页面运行及与页面 DOM 交互。

**AI API 域名：**
> 扩展需要直接向用户配置的 AI 服务商 API 端点发送 HTTPS 请求，以获取回答内容分析和反驳生成结果。请求由扩展后台脚本（service worker）直接发起，不经任何第三方中转，且仅传输当前回答的文本内容及用户的 API Key。

### 需使用 activeTab 权限的理由

```
扩展需要获取用户当前正在浏览的标签页信息（URL、页面标题），用于判断当前页面是否为知乎内容页，以及向后台脚本传递当前页面上下文。该权限仅在用户主动点击扩展图标或页面内按钮时触发，不会静默访问标签页内容。
```

### 需使用 storage 权限的理由

```
扩展需要使用 chrome.storage.local 在浏览器本地持久化存储以下数据：用户的 API Key、AI 提供商选择、模型配置、反驳风格偏好、功能开关状态以及最近 10 条生成历史记录。所有数据仅保存在用户本地设备，不上传至任何远程服务器。
```

### 数据使用情况确认

> 在隐私权规范标签页底部，勾选「此产品遵守 Chrome Web Store 开发者计划政策，包括其用户数据隐私政策」复选框。

## 二、Product Hunt 中文版发布

> 策略：PH 核心用户为英文使用者，纯中文发布会损失大量自然流量。若产品只面向中文用户，可纯中文发布；否则建议至少 Name + Tagline 使用双语。

### 产品信息

| 字段 | 填写内容 |
|------|---------|
| **Name** | `Zhihu Rebuttal` 或 `知乎反驳助手 Zhihu Rebuttal` |
| **Tagline** | `一键生成有理有据的知乎反驳草稿，AI 辅助但不替代人工判断` |
| **Category** | `Browser Extensions` + `AI Tools` + `Productivity` |
| **Website** | Chrome Web Store 链接 |

### Description（500 字符以内）

```
知乎反驳助手是一款 Chrome 扩展，帮助你在知乎上看到错误回答时，快速生成有理有据的反驳草稿。

核心功能：
• 一键生成反驳 — 回答下方注入按钮，AI 分析并生成草稿
• 五种错误检测 — 事实错误、逻辑谬误、历史虚无、数据造假、科学错误
• 三种风格 — 温和理性、直接犀利、学术严谨
• 隐私优先 — API Key 本地存储，数据直连 AI 厂商

支持 DeepSeek、Kimi、OpenAI、Claude 及自定义 API。所有内容须经人工审核后发布。
```

### First Comment（发布者首条评论）

```
Hey PH 的朋友们 👋

我是这个工具的开发者。

做这个东西的契机很简单：我在知乎上混了很多年，每天都能看到各种事实错误、滑坡论证、历史虚无主义的回答获得高赞。想反驳，但写一条有理有据的回复至少要花半小时查资料、组织语言。时间一长，大多数人就沉默地划走了。

我觉得这不应该是理性讨论的常态。所以做了这个扩展，目标不是让人去当「杠精」，而是降低「有理有据地纠错」的时间成本。

几个设计上的坚持：

• 不自动发布任何内容 — 所有生成结果必须人工审核
• 支持国产模型 DeepSeek 和 Kimi — 国内用户无需特殊网络，成本低
• 零后端 — 没有服务器，没有数据收集，API Key 只存在你的浏览器里

如果你也是知乎用户，可以在 Chrome 商店搜索「知乎反驳助手」试试。不是知乎用户也欢迎聊聊，我正在考虑支持 Reddit 和 X，想听听你们觉得哪个平台更需要这种工具。

有任何问题可以直接在这条下面问，我会尽量回复。

谢谢 🙏
```

## 四、知乎官网营销

> 核心原则：知乎对推广内容有明确管控，在别人的评论区硬广风险极高。应以「经验分享」姿态而非「产品推广」姿态出现。

### 各推广方式风险等级

| 推广方式 | 风险等级 | 说明 |
|---------|---------|------|
| 在相关问题下写高质量回答（附产品） | 🟡 中低 | 真实体验分享通常安全，但外链可能被折叠 |
| 写专栏文章《我做了一个知乎反驳助手》 | 🟢 低 | 专栏是创作分享，知乎鼓励，最安全 |
| 在评论区发「试试我的工具」 | 🔴 高 | 容易被举报为广告，删评甚至封号 |
| 批量复制粘贴相同内容到多个问题 | 🔴 极高 | 会被反作弊系统直接判定为 Spam |
| 个人简介放产品名 | 🟢 低 | 几乎不会管 |
| 在回答底部加 P.S. 签名 | 🟡 中 | 偶尔可以，每条都加会被限流 |
| 发「想法」短内容 | 🟢 低 | 适合发更新日志、使用技巧 |

### 专栏文章推荐结构

```
标题：《我花了两周做了一个知乎反驳助手：从动机到实现》

内容结构：
1. 我在知乎上遇到的痛点（事实错误、逻辑谬误没人纠正）
2. 为什么手动反驳成本太高
3. 产品设计的原则（人工审核优先、不自动发布、隐私保护）
4. 技术实现的关键点（内容提取、Prompt 设计、知乎 DOM 适配）
5. 遇到的坑和反思
6. 未来 Roadmap
7. 最后一段：如果你感兴趣，可以在 Chrome Web Store 搜索「知乎反驳助手」
```

### 个人简介写法

```
Chrome扩展「知乎反驳助手」开发者｜用AI辅助理性讨论，人工审核优先
```

**配合主页其他元素：**
- 置顶一篇介绍产品的专栏文章
- 背景图可放产品 Slogan 图（如「AI 辅助，人做判断」）
- 保持最新动态中有产品相关的「想法」或文章

### 评论区应对「bot 质疑」策略

若在自己的评论下被质疑是 AI/bot 生成：

> 确实用了辅助工具，但每一条都是我审过才发的。不在这儿展开说了，感兴趣可以私信~

**核心原则：** 解释但不推广，或引导到私信/主页，不要在别人的回答评论区里展开产品宣传。

### 知乎推广节奏

| 阶段 | 时间 | 动作 | 目的 |
|------|------|------|------|
| 预热 | 第 1 周 | 以个人身份回答 2-3 个相关问题（不带产品） | 积累账号权重 |
| 首发 | 第 2 周 | 发专栏文章《我做了一个知乎反驳助手》 | 安全的主力推广载体 |
| 引流 | 第 3 周 | 在 1-2 个精准问题下回答，末尾放专栏文章链接 | 从问题流量导到专栏 |
| 持续 | 之后 | 发「想法」更新产品迭代、用户反馈 | 维持存在感，不打扰 |
| 收割 | 长期 | 个人简介永久放链接，每次相关回答的签名区自然提及 | 被动流量 |

## 五、跨平台通用原则

### 文案策略

| 平台 | 语言 | 核心策略 | 转化路径 |
|------|------|---------|---------|
| Chrome Web Store | 中文 | 说明用途 + 解决信任问题（隐私、不自动发布） | 安装扩展 |
| Product Hunt | 中文（建议双语） | Build in Public 故事 + 技术细节 | 关注/下载/传播 |
| X.com | 中文 | Thread 叙事 + 钩子前置 | 评论区链接 → CWS |
| 知乎 | 中文 | 经验分享姿态，硬广是自杀 | 专栏文章 → CWS |

### 安全红线

1. **不要在自己的产品场景里硬推产品**（如知乎评论区发广告），会被反噬
2. **X 主帖不放外链**，放评论区
3. **PH Description 控制在 500 字符内**，详细内容放 First Comment
4. **CWS 审核文案要诚实**，不要夸大功能或隐瞒权限用途
5. **所有平台都要强调「人工审核」**，这是建立信任的核心差异点
