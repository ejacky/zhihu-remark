# 知乎反驳助手 - 产品需求文档 (PRD)

> 版本：v1.0.0  
> 更新日期：2026-05-11  
> 状态：已实现

---

## 1. 产品概述

### 1.1 背景
知乎作为中国最大的知识问答社区，汇聚了大量用户生成的内容。然而，部分内容存在明显的事实错误、逻辑谬误、历史虚无主义等问题。这些错误信息可能误导读者，损害社区讨论质量。

手动撰写反驳评论需要用户具备相关知识储备和充足的时间精力。本工具旨在通过 AI 技术，帮助用户快速生成有理有据的反驳评论草稿，降低理性纠错门槛，提升社区内容质量。

### 1.2 产品定位
- **目标用户**：经常浏览知乎、关注内容质量、愿意参与理性讨论的用户
- **核心价值**：AI 辅助生成有理有据的反驳评论，节省用户时间，提高反驳质量
- **产品形态**：Chrome/Edge 浏览器扩展

### 1.3 产品原则
1. **人工审核优先**：所有 AI 生成内容必须经过用户审核后才能发布
2. **理性客观**：反驳基于事实和逻辑，禁止人身攻击
3. **用户自主**：用户完全控制是否生成、是否发布、如何修改
4. **隐私保护**：API Key 仅存储在本地，不上传任何第三方服务器

## 2. 用户故事

### 2.1 核心用户场景

**场景一：事实纠错**
> 小明在知乎上看到一篇回答，声称"中国的 GDP 在 2020 年超过了美国"。他记得这与事实不符，但一时找不到准确数据。他点击"生成反驳"按钮，AI 识别出事实错误并提供了正确的 GDP 数据和来源，小明审核后发布评论纠正。

**场景二：逻辑谬误识别**
> 小红看到一篇回答使用了滑坡论证（"如果不禁止游戏，青少年都会荒废学业，国家就会灭亡"）。她想要指出其中的逻辑问题，但不知道如何表达更得体。AI 生成了温和而有力的逻辑分析，帮助她清晰表达观点。

**场景三：历史虚无主义反驳**
> 老李看到一篇回答歪曲某段历史事实。作为历史爱好者，他有很多想说的，但组织语言需要时间。AI 快速生成了基于史料的反驳，引用了权威历史来源，老李补充个人观点后发布。

### 2.2 用户画像

| 画像 | 特征 | 需求 |
|------|------|------|
| 知识型用户 | 关注内容质量，有专业背景 | 快速生成专业、准确的反驳 |
| 普通浏览者 | 有常识判断但缺乏专业知识 | 获取可靠信息和反驳思路 |
| 社区活跃者 | 经常参与讨论 | 提高讨论效率和质量 |

## 3. 功能需求

### 3.1 核心功能

#### FR-001：按钮注入
- **描述**：在知乎回答的评论操作栏自动注入"🛡️ 生成反驳"按钮
- **优先级**：P0
- **验收标准**：
  - 按钮出现在每个回答的评论按钮旁边
  - 不影响知乎原有功能
  - 支持动态加载的回答（滚动加载、展开更多）

#### FR-002：内容提取
- **描述**：自动提取回答的标题、正文、作者、赞同数等信息
- **优先级**：P0
- **验收标准**：
  - 准确提取回答正文（支持富文本）
  - 兼容知乎新版和旧版页面结构
  - 支持专栏文章

#### FR-003：AI 错误分析
- **描述**：调用云端 AI API 分析回答中的错误
- **优先级**：P0
- **验收标准**：
  - 识别事实错误、逻辑谬误、历史虚无主义、数据造假、科学错误
  - 返回结构化分析结果（错误类型、位置、说明）
  - 分析时间不超过 10 秒

#### FR-004：反驳生成
- **描述**：基于错误分析生成反驳评论
- **优先级**：P0
- **验收标准**：
  - 生成不超过 500 字的反驳评论（不设下限，能短则短）
  - 语气符合用户选择的风格（温和/直接/学术）
  - 包含错误指正和正确信息
  - 以争取中立围观者为目标，不出现"这回答跑偏了吧"等对作者框架的评价（元评论）
  - 反驳围绕原文的核心断言，不攻击原文措辞或提问态度
  - 时效表述（最近/上个月/前几年/旧闻）以生成时的当前日期为基准推算，不得凭模型印象猜测
  - 可选择性引用来源，但必须人味化表达（"之前新闻都报过"），不出现"公开报道显示""数据显示"等报道腔，整体不易被识别为 AI 生成

#### FR-005：评论框填充
- **描述**：将生成的反驳自动填入知乎评论输入框
- **优先级**：P0
- **验收标准**：
  - 自动展开评论区（如未展开）
  - 正确填入富文本编辑器
  - 保留换行格式

### 3.2 配置功能

#### FR-006：API 配置
- 支持 DeepSeek、Kimi、OpenAI、Claude、自定义 API
- 配置 API Key、模型、Base URL
- **API Base URL 与模型名称对所有提供商均可手动填写**（含内置提供商）：官方地址与模型名会随时间变化（换域名、模型上/下线、走代理或镜像），内置值只作为默认地址与建议，留空才回退到内置值
- Temperature 和 Max Tokens 调节
- 保存时按**实际生效的地址**向浏览器申请该域名的访问授权（Chrome 可选权限），未授权则不保存配置；留空使用内置地址时不重复弹窗
- 地址校验（不通过则不保存，并给出可操作提示）：畸形地址（只有协议、非 http(s) 协议）、误把完整端点（`/chat/completions`、`/messages`）填进 Base URL、以及无法授权的明文 http 域名（仅 `localhost` / `127.0.0.1` 的 http 可授权）
- API Base URL 自动规范化（补全协议、去末尾斜杠），本地地址（localhost / 127.0.0.1）默认按 http 处理
- 兼容要求额外会话头的 OpenAI 兼容网关（如 OpenCode Go / Zen）：自动附带 `x-opencode-session`，无需用户配置

#### FR-007：风格选择
- 温和理性（默认）：平和建设性
- 直接犀利：鲜明有力
- 学术严谨：规范引用

#### FR-008：错误类型开关
- 用户可选择启用/禁用特定错误类型的检测
- 默认全部启用

#### FR-009：功能开关
- 显示错误分析面板
- 自动填充评论框
- 要求标注来源
- 启用历史记录

### 3.3 辅助功能

#### FR-010：历史记录
- 保存最近 10 条生成记录
- 显示问题标题、作者、错误类型、生成时间
- 支持一键跳转原问题

#### FR-011：通知提示
- 操作成功/失败提示
- API Key 未配置提醒
- 内容提取失败提醒

#### FR-012：最新模型版本支持
- 动态展示各 AI 提供商的常用模型版本作为输入建议
- 切换提供商时自动更新建议列表
- **模型名称为文本输入**，所有提供商（含内置提供商）都支持手动输入任意模型名，不局限于建议列表
- 模型名称为必填：留空时保存被拦下并提示（避免把内置默认模型名误发给自定义端点）
- 兼容旧配置（已保存的不在建议列表中的模型仍可正常使用）

#### FR-013：重新生成反驳
- 在错误分析面板中提供"重新生成"按钮
- 重新生成时要求 AI 换一个角度、换一种表达方式
- 重新生成失败时显示友好错误提示，恢复按钮状态
- 重新生成流程与首次生成保持一致（分析 → 使用 → 填充）

## 4. 非功能需求

### 4.1 性能
- 按钮注入延迟 < 500ms
- AI 响应时间 < 15 秒（含网络请求）
- 扩展包体积 < 500KB

### 4.2 兼容性
- Chrome 88+ / Edge 88+
- 支持知乎新版页面结构
- 支持 Windows / macOS / Linux

### 4.3 安全性
- API Key 仅使用 chrome.storage.local 存储
- 所有网络请求直接发往用户配置的 API 端点
- 不收集、不上传任何用户数据到第三方

### 4.4 可靠性
- 内容提取失败时给出明确提示
- API 调用失败时显示友好错误信息
- 知乎 DOM 更新时有降级策略

## 5. 界面原型

### 5.1 知乎页面注入效果
```
[赞同 1.2K] [评论 342] [收藏] [分享] [🛡️ 生成反驳] [喜欢]
```

### 5.2 错误分析面板
```
┌─────────────────────────────┐
│ 🔍 错误分析              [✕] │
├─────────────────────────────┤
│ [❌ 事实错误] [🔄 逻辑谬误]  │
│ 置信度：高 · 2 处错误        │
├─────────────────────────────┤
│ 错误详情                     │
│ ┌─────────────────────────┐ │
│ │ 事实错误                 │ │
│ │ 原文：...                │ │
│ │ 纠正：...                │ │
│ └─────────────────────────┘ │
├─────────────────────────────┤
│ 该回答存在事实错误和逻辑   │
│ 谬误，主要表现为...        │
├─────────────────────────────┤
│ 📝 生成的反驳        [复制] │
│ ┌─────────────────────────┐ │
│ │ 反驳内容预览...        │ │
│ └─────────────────────────┘ │
│ ✏️ 优化这次生成...         │ │
│ 💡 我理解你的要求：        │ │
│ 自然、简短、像真人说话 [修改]│ │
├─────────────────────────────┤
│ [👍 有用]  [重新生成] [使用此反驳] │
└─────────────────────────────┘
```
- 按住标题栏可拖动面板位置
- 按 `Esc` 或点击右上角 ✕ 按钮关闭面板
- 关闭后再次点击同一回答的按钮，直接恢复面板状态，不重新生成
- 支持一键复制生成的反驳内容
- 支持展开「优化这次生成」添加自定义要求或选择快捷反馈后重新生成
- 系统会自动整理多次自定义要求，提炼核心意图摘要，用户可手动修改

### 5.3 设置页面
- Tab 导航：API 设置 | 风格与类型 | 功能开关 | 历史记录 | Prompt 预览

## 6. 风险与限制

### 6.1 产品风险
| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| AI 生成不准确反驳 | 中 | 高 | 强制用户审核，Prompt 要求标注不确定内容 |
| 被知乎检测为自动化工具 | 低 | 高 | 不自动发布，完全人工触发 |
| 知乎页面结构更新 | 高 | 中 | 多策略内容提取，定期维护 |
| API 费用过高 | 低 | 中 | 支持低成本模型（DeepSeek、GPT-4o-mini） |

### 6.2 法律与合规
- 用户需自行承担使用 AI 生成内容的责任
- 不保证 AI 分析 100% 准确
- 建议用户在发布前核实关键事实

---

## 7. 成功指标

- **激活率**：安装用户中至少使用一次生成功能的占比 > 30%
- **采纳率**：生成反驳后用户实际发布评论的占比 > 50%
- **满意度**：用户手动修改幅度 < 30%（说明生成质量较高）
