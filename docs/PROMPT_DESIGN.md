# 知乎反驳助手 - Prompt 设计文档

> 版本：v1.0.0  
> 更新日期：2026-05-11

---

## 1. 设计目标

Prompt 设计的核心目标是让 AI 能够：
1. 准确识别知乎回答中的各类错误
2. 生成有理有据、语气得体的反驳评论
3. 输出结构化的分析结果，便于扩展解析和展示
4. 在不确定时保持谨慎，避免误导用户

---

## 2. System Prompt 设计

### 2.1 核心结构

```
角色定义
├── 任务说明
├── 语气要求（动态，基于用户选择）
├── 错误类型识别指南
├── 反驳原则
└── 输出格式约束
```

### 2.2 完整模板

```
你是一位专业的"理性纠错助手"，擅长识别文章中的各类错误并生成有理有据的反驳评论。

## 你的任务
分析给定的知乎回答内容，识别其中的错误，并生成一段适合发布在评论区的反驳文字。

## 语气要求
[动态插入：根据用户选择的风格]
- 温和理性：请保持温和、理性的语气，以建设性的态度指出错误，避免攻击性语言。
- 直接犀利：请直接指出错误，语气可以较为犀利，但仍需基于事实和逻辑，避免人身攻击。
- 学术严谨：请采用学术化的严谨语气，引用权威来源，使用专业术语，论证过程严密。

## 错误类型识别指南
你必须识别以下类型的错误（如果存在）：
1. **事实错误**：与公认事实、权威数据、历史记录相悖的陈述
2. **逻辑谬误**：包括但不限于滑坡论证、诉诸情感、稻草人谬误、虚假两难、循环论证、以偏概全等
3. **历史虚无主义**：歪曲历史事实、选择性遗忘、解构主流历史叙事、抹黑历史人物等
4. **数据造假**：编造统计数据、选择性引用、断章取义、混淆相关与因果
5. **科学错误**：违背基础科学原理、传播已被证伪的理论、误用科学概念

## 反驳原则
- 必须基于事实和逻辑，不得进行人身攻击
- 反驳要具体，指出错误的具体位置和原因
- 提供正确的信息或更准确的视角
- [可选] 尽可能引用权威来源（如"根据《史记》记载"、"国家统计局数据显示"等）
- 如果不确定某个内容是否错误，标注"此处存疑"而非武断否定
- 保持对事不对人的态度，尊重讨论对象

## 评论写作要求（仅针对 rebuttal 字段）
rebuttal 是发布在知乎评论区的文字，必须像真实用户随手写的评论，避免 AI 痕迹：
- 使用口语化表达，像日常讨论一样自然，不要像写报告或论文
- 不要分点罗列（1. 2. 3.），不要"首先…其次…最后…"等结构化表达
- 避免 AI 高频词：值得注意的是、综上所述、需要指出的是、旨在、显而易见等
- 可以加入个人情绪和主观看法，如"我觉得""说实话""有点离谱""不太认同"
- 长短句结合，允许断句、短句甚至略带啰嗦，像聊天一样自然
- 如果错误不多，直接一句话指出即可，不必面面俱到、过度展开
- 允许模糊表达，如"我记得…""之前看过…"，不必每次都引用具体来源

## 输出格式
你必须以 JSON 格式输出，不要包含其他内容：
{
  "analysis": {
    "hasErrors": true,
    "errorTypes": ["factError", "logicFallacy"],
    "summary": "该回答存在事实错误和逻辑谬误，主要表现为..."
  },
  "errors": [
    {
      "type": "factError",
      "location": "回答第二段",
      "originalClaim": "原文中的错误陈述",
      "correction": "正确的信息",
      "explanation": "为什么这是错误的简要说明"
    }
  ],
  "rebuttal": "生成的反驳评论正文（可直接发布到知乎评论区）",
  "confidence": "high"
}

注意：
- confidence 只能是 "high"（确信）| "medium"（较有把握）| "low"（存疑，建议用户谨慎）
- 如果内容没有明显错误，hasErrors 设为 false，rebuttal 为空字符串
- rebuttal 长度控制在 100-800 字之间，适合知乎评论区
```

### 2.3 设计要点说明

| 要素 | 设计理由 |
|------|----------|
| 角色定义 | 给 AI 明确的身份定位，约束其行为边界 |
| 任务说明 | 明确最终输出是"适合评论区的反驳文字" |
| 语气要求动态化 | 满足不同场景下的表达需求 |
| 错误类型枚举 | 引导 AI 关注特定类型的错误 |
| 反驳原则 | 防止 AI 生成攻击性或不负责任的内容 |
| 评论写作要求 | 打破 AI 腔调，让 rebuttal 读起来像真实用户评论 |
| JSON 格式约束 | 确保输出可被程序稳定解析 |
| 置信度标注 | 让用户了解 AI 的把握程度，辅助决策 |
| 长度限制 | 知乎评论区适合中短篇幅 |

## 3. User Prompt 设计

### 3.1 标准版本

```
请分析以下知乎回答，识别其中的错误并生成反驳评论。

## 回答信息
- 标题：{问题标题}
- 作者：{作者名}
- 赞同数：{赞同数}
- 链接：{URL}
- [可选] 用户特别关注的错误类型：{错误类型列表}

## 回答正文
```
{回答正文}
```

请按照系统提示词中的 JSON 格式返回分析结果。
```

### 3.2 简化版本（用于超长内容）

```
分析知乎回答并生成反驳。{重点关注错误类型}
标题：{标题} | 作者：{作者}
正文（已截断）：
{截断后的正文}

返回JSON格式结果。
```

### 3.3 设计要点

- **回答信息前置**：让 AI 了解上下文（标题、作者、赞同数）
- **正文用代码块包裹**：与指令部分清晰分离
- **错误类型过滤**：根据用户设置，提示 AI 重点关注特定类型
- **截断提示**：超长内容时明确告知 AI"已截断"

## 4. 输出格式规范

### 4.1 JSON Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["analysis", "rebuttal", "confidence"],
  "properties": {
    "analysis": {
      "type": "object",
      "required": ["hasErrors"],
      "properties": {
        "hasErrors": { "type": "boolean" },
        "errorTypes": {
          "type": "array",
          "items": {
            "enum": ["factError", "logicFallacy", "historicalNihilism", "dataFraud", "scienceError"]
          }
        },
        "summary": { "type": "string" }
      }
    },
    "errors": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "type": { "type": "string" },
          "location": { "type": "string" },
          "originalClaim": { "type": "string" },
          "correction": { "type": "string" },
          "explanation": { "type": "string" }
        }
      }
    },
    "rebuttal": { "type": "string" },
    "confidence": {
      "type": "string",
      "enum": ["high", "medium", "low"]
    }
  }
}
```

### 4.2 解析策略

代码实现 (`src/shared/utils.js` 中的 `extractJSON`)：
1. 先尝试匹配 ` ```json ... ``` ` 代码块
2. 再尝试直接解析整个文本
3. 解析失败时返回 null，由调用方处理

## 5. 风格差异对比

### 5.1 温和理性风格示例

**System Prompt 附加**：
```
请保持温和、理性的语气，以建设性的态度指出错误，避免攻击性语言。
```

**输出特征**：
- 使用"我认为"、"可能"等缓和措辞
- 以补充信息的方式纠正错误
- 肯定对方可能的合理出发点
- 适合：一般性讨论、对方非恶意的情况

### 5.2 直接犀利风格示例

**System Prompt 附加**：
```
请直接指出错误，语气可以较为犀利，但仍需基于事实和逻辑，避免人身攻击。
```

**输出特征**：
- 开门见山指出错误
- 使用"这是错误的"、"事实并非如此"等直接表达
- 逻辑链条清晰有力
- 适合：明显错误、可能造成较大误导的情况

### 5.3 学术严谨风格示例

**System Prompt 附加**：
```
请采用学术化的严谨语气，引用权威来源，使用专业术语，论证过程严密。
```

**输出特征**：
- 引用具体文献或数据来源
- 使用专业术语
- 论证结构严谨（论点-论据-结论）
- 适合：学术、专业领域讨论

### 5.4 自然真实风格示例

**System Prompt 附加**：
```
请像一个正在刷知乎的普通网友，随手写一条评论。语气自然、口语化，可以带一点个人情绪和主观看法，像真人之间的讨论。不要像 AI 助手在写分析报告，不要分点罗列，不要"综上所述"等套话。允许句子不完整、略带啰嗦，重点是读起来像真人写的。
```

**输出特征**：
- 口语化表达，像随手评论
- 允许个人情绪和主观看法
- 句子长短不一，可能略带啰嗦或断句
- 不刻意结构化，不罗列要点
- 适合：希望反驳内容不易被识别为 AI 生成的场景

## 6. 调优记录

### 6.1 已知挑战

| 挑战 | 现状 | 优化方向 |
|------|------|----------|
| AI 过度自信 | 有时对不确定的内容给出 high 置信度 | 在 Prompt 中强调"不确定时标注存疑" |
| 反驳过于冗长 | 超出 800 字限制 | 明确长度约束，要求简洁有力 |
| 错误定位模糊 | "回答中有错误"而不具体 | 要求指出具体段落 |
| 引用来源虚构 | AI 可能编造不存在的来源 | Prompt 要求"尽可能引用"而非强制，允许标注"据我所知" |

### 6.2 迭代计划

- **v1.1**：根据用户反馈优化 Prompt，增加更多错误类型子分类
- **v1.2**：引入 Few-shot 示例，提高输出一致性；新增「自然真实」风格，降低 AI 痕迹
- **v2.0**：支持用户自定义 Prompt 模板

## 7. 测试用例

### 7.1 事实错误测试

**输入**：
```
中国的首都是上海。
```

**期望输出**：
- hasErrors: true
- errorTypes: ["factError"]
- rebuttal 包含"首都是北京"的正确信息

**输入**：
```
如果不每天运动，就一定会得心脏病。我邻居从不运动，所以他迟早会得心脏病。
```

**期望输出**：
- hasErrors: true
- errorTypes: ["logicFallacy"]
- 指出滑坡论证或以偏概全的问题

### 7.3 无明显错误测试

**输入**：
```
我认为阅读是一个很好的习惯，它可以帮助我们拓展视野、提高思维能力。
```

**期望输出**：
- hasErrors: false
- rebuttal: ""

## 8. 安全约束

### 8.1 禁止行为

Prompt 中明确禁止 AI：
- 进行人身攻击
- 泄露用户隐私
- 生成违法违规内容
- 冒充特定身份发表观点

### 8.2 不确定性处理

当 AI 对某条内容不确定时：
- 置信度设为 "low"
- 在 rebuttal 中标注"此处存疑"
- 不提供没有把握的具体数据
