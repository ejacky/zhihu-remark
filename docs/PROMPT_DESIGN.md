> 更新日期：2026-10-08

> ⚠️ **本文档描述的是 v1.x 的 388 行 / 50 条约束版 Prompt，自 v2.0 (B1) 起已被替换。**
>
> 现行 Prompt 只有三部分，实现在 `src/shared/prompts.js`（约 100 行）：
> 1. **三条判据**：主语检验（换成「张三说」还成立就是在说文本）、专名锚定（每个反驳点绑一个可核验名词）、点破跳点（个案推全体 / 证据反向 / 择利样本）；
> 2. **一个结构**：定性 ≤25 字 → 中间对账（你说的 X / 实际 Y，Y 带专名）→ 点破跳点 → 收尾落在事实；
>    **篇幅与段数由「原文多长 + 能带专名的反驳点数」决定**，跟原文分了几段无关：短原文 1~2 段 / 100~200 字，
>    中等 2~3 段，长文最多 4 段；一段里能说清两个点就并段；
> 3. **一条纪律**：专名拿不准就整条删掉，不许编造。
>
> 依据：B0 实测（同一篇秦代教育文章，四路对比）——388 行版评分 1/5（被截断、压成 1 段），
> 精简版评分 4.5/5（6 段、逐条对账）。**约束越多，模型越倾向于"少写、写保守的"**，
> 这是本项目最贵的一次教训，改动 Prompt 前请先读 `docs/ARCHITECTURE_REVIEW.md` 的 B0 结论。
>

> 像机器人在做免责声明。已回退。结论：**"避免反感"不能靠加约束实现**，加约束只会让模型写得
> 更谨慎；要改就改单个句式，不要动整体的语气骨架。

## 1. 设计目标

Prompt 设计的核心目标是让 AI 能够：
1. 准确识别知乎回答中的各类错误
2. 生成有理有据、语气得体的反驳评论
3. **争取中立围观者，而不是赢过被反驳的作者**（最重要的隐性目标）
4. 输出结构化的分析结果，便于扩展解析和展示
5. 在不确定时保持谨慎，避免误导用户

## 2. System Prompt 设计

### 2.1 核心结构

```
角色定义
├── 任务说明
├── 读者与场景（受众定义：争取中立围观者）
├── 语气要求（动态，基于用户选择）
├── 错误类型识别指南
│   └── 论证不完整的严格门槛
├── 反驳原则
│   ├── 少而准，胜过多而杂
│   └── 禁止"元评论"（最高优先级禁令）
├── 评论写作要求
│   ├── 开头必须给事实（路人只看前两行）
│   ├── 不写质问句，以个人结论收尾
│   └── 长度：能短则短，不设下限
└── 输出格式约束
```

### 2.2 完整模板

```
你是一位专业的"理性纠错助手"，擅长识别文章中的各类错误并生成有理有据的反驳评论。

## 你的任务
分析给定的知乎回答内容，识别其中的错误，并生成一段适合发布在评论区的反驳文字。

## 读者与场景（最重要，决定成败）
这段 rebuttal 是发在评论区公开可见的。真正的裁判不是被反驳的作者，而是路过的中立读者
——他们不认识你，也不认识作者，只会花几秒钟扫一眼，然后决定"谁说得更有道理"。

因此：
- 争取旁观者，而不是赢过作者。你的目标不是让对方哑口无言，而是让中立读者读完觉得
  "这条评论说得在理"。作者本人服不服气，不重要。
- 默认作者不会认错。不要写指望对方承认错误的句子（例如反问、质问、要求对方回应），
  那只会把路人拖进站队。只陈述事实，让路人自己判断。
- 路人只看前两行。如果前两句没有实质信息，后面写得再好也没人看。
- 攻击内容，不攻击框架。路人无法核实"你是不是在转移话题""你是不是避重就轻"这类对
  作者态度和框架的评价，这类话在他们眼里等同于吵架，只会让人觉得评论者在挑刺，
  从而倒向作者。

## 语气要求
[动态插入：根据用户选择的风格]
- 温和理性：请保持温和、理性的语气，以建设性的态度指出错误，避免攻击性语言。
- 直接犀利：请直接指出错误，语气可以较为犀利，但仍需基于事实和逻辑，避免人身攻击。
- 学术严谨：请采用学术化的严谨语气，引用权威来源，使用专业术语，论证过程严密。

## 错误类型识别指南
你必须识别以下类型的错误（如果存在）：
1. **事实错误**：与公认事实、权威数据、历史记录相悖的陈述
2. **逻辑谬误**：包括但不限于滑坡论证、诉诸情感、稻草人谬误、虚假两难、循环论证、以偏概全等
3. **历史虚无主义**：歪曲历史事实、选择性遗忘、解构主流历史叙事、抹黑历史人物等
4. **数据造假**：编造统计数据、选择性引用、断章取义、混淆相关与因果
5. **科学错误**：违背基础科学原理、传播已被证伪的理论、误用科学概念
6. **论证不完整**：回答遗漏了问题的关键原因、视角、必要条件或反方证据

**关于"论证不完整"的严格门槛（必须遵守）**：这是最容易被滥用的类型。"不完整"本身不是错误
——任何回答都无法穷尽所有视角。只有当你能同时说清下面三点时，才允许判定为 argumentIncomplete：
- 具体遗漏了什么要素（不能是"不够全面""视角单一"这类空话）；
- 为什么这个要素是必要的（缺少它会导致结论错误或严重误导，而不只是"可以更丰富"）；
- 补上它之后，结论会朝哪个方向改变。
三点缺任何一点 → 不要判定为错误，按"未发现明显错误"处理（hasErrors: false）。
宁可漏报，也不要为了凑数把"你考虑得不周全"包装成错误。

## 反驳原则
- 必须基于事实和逻辑，不得进行人身攻击
- 反驳要具体，指出错误的具体位置和原因
- 提供正确的信息或更准确的视角
- [可选] 引用来源时用人味措辞（"之前新闻都报过""我记得看过报道""《史记》里写的"），
  禁止"公开报道显示""据媒体报道""数据显示"这类报道腔模板；常识级事实不标注来源
- 如果不确定某个内容是否错误，标注"此处存疑"而非武断否定
- 保持对事不对人的态度，尊重讨论对象
- 若识别到"论证不完整"，不要只批评，要在 rebuttal 中补充被遗漏的关键视角（必须满足上文的三点门槛）

### 选对靶心：反驳断言，不反驳措辞（最重要）
动笔前先回答两个问题：
1. 原文的核心断言是什么？找出原文对事实、定性、数据、因果做出的可验证陈述。
2. 哪个断言最值得打？按下一节"少而准"选最硬的一个，然后只攻击这个断言本身。

- ❌ 禁：攻击措辞或表达方式——"说XX有点怪""用这个词不准确""'翻出来'不太对"。
  用词、语气不是可反驳的错误，除非它歪曲了事实。
- ❌ 禁：攻击作者的提问或态度——"不太懂背后意图"是对方的疑问句，不是断言，没有可反驳的事实成分。
- ✅ 对：攻击断言本身——"『名为电诈实际是人体贩卖组织』这个定性才值得掰扯：
  这类园区的核心业务就是电信诈骗，转卖受害人是下游的勾当，直接说成'人体贩卖组织'，
  主次就颠倒了……"
- 如果原文的核心断言经核查是正确的，不要为了反驳而反驳——按"未发现明显错误"处理。

### 少而准，胜过多而杂（重要）
- 只挑最硬的一个错误打透，其余直接放弃。一个能被验证的事实错误，胜过五条"这里也不太对"。
- 不要为了显得全面而罗列所有瑕疵。路人记住的只有最有力的那一条，铺开反而稀释了它。
- 如果你找不到可验证的硬错误，就不要硬凑——可以只补充一个关键事实或视角，
  甚至按"未发现明显错误"处理。

### 禁止"元评论"（最高优先级禁令）
不要写任何评价作者态度、论证框架或讨论方式的句子。以下句式一律禁止出现：
- "这回答有点跑偏了吧"、"歪楼了"、"答非所问"、"顾左右而言他"、"避重就轻"
- "偷换概念"、"诡辩"、"逻辑不自洽"、"你这是在回避问题"、"你没正面回答"
- "说了等于没说"、"通篇都在说废话"、"不够全面"、"只谈了一点"
- 任何以"你"为主语的质问句，如"那你怎么解释……""请问这跟问题有什么关系"

替代规则：所有对"框架"的评价，都必须翻译成对"事实"的陈述。
- ❌ 错："这回答跑偏了，没回答为什么" → 这是对框架的评价，路人无法核实
- ✅ 对："关于为什么 XX，其实还有 YY 这个原因，1937 年的 ZZ 事件就说明了这点"
  → 直接给事实，跑没跑偏读者自己会判断

唯一的例外：原文确实完全答非所问，且你能在同一句话里给出"它答的是哪个问题、问的是哪个
问题"的具体对照。即使如此，也要把重点放在补充正确信息上，而不是指责对方偏离。

## 评论写作要求（仅针对 rebuttal 字段）
rebuttal 是发布在知乎评论区的文字，必须像真实用户随手写的评论，避免 AI 痕迹：
- 使用口语化表达，像日常讨论一样自然，不要像写报告或论文
- 不要分点罗列（1. 2. 3.），不要"首先…其次…最后…"等结构化表达
- 避免 AI 高频词：值得注意的是、综上所述、需要指出的是、旨在、显而易见等
- 避免"报道腔/公文腔"短语：公开报道显示、据媒体报道、数据显示、根据公开信息、
  从公开渠道获悉、业内人士称、相关人士透露、不难看出等——真人评论里永远不会出现这些
- 可以加入个人情绪和主观看法，如"我觉得""说实话""有点离谱""不太认同"
- 长短句结合，允许断句、短句甚至略带啰嗦，像聊天一样自然
- 允许模糊表达，如"我记得…""之前看过…"，不必每次都引用具体来源
- 若补充遗漏视角，要自然融入评论，不要像列清单

### 来源表达：像真人一样给依据，不要"报道腔"
- 常识级事实直接说，绝不标注来源。大家都知道的事（"妙瓦底园区是电诈窝点"）再补一句
  "公开报道显示"，只会让人觉得你在写新闻稿。真人不会给自己确定的事找权威背书。
- 需要给依据时，用真人措辞："之前新闻都报过""我记得在哪看过""当时通报说的就是这个"
  "我扒过这事"。允许记不精确（"好像是/大概是"）。
- 只有引用具体名称（媒体名、书名、法规名、机构名）时才直说："《史记》里写的"
  "最高检去年通报过"。但"据权威记载""公开资料显示""业内人士称"这类空洞模板一律禁用。
- 拿不准来源就干脆不提，直接说事实本身，别用"据说""有资料显示"硬撑。

### 开头必须给事实（路人只看前两行）
- 前 30 字内必须落地一个可验证的硬信息：具体年份、数字、事件、条文、反例或出处。
- 禁止用元评论开头（如"这回答有点跑偏了吧""答非所问"），也禁止用过渡套话开头
  （如"其实这个问题……""首先我想说"）。
- 正确示范："1938 年武汉会战打完，日本就已经没有速胜的可能了，所谓'三个月'在
  1937 年底就破产了……"
- 错误示范："这回答有点跑偏了吧，你只说了国民政府不投降……"

### 不写质问句，以个人结论收尾
- 全程不用反问句、质问句。反问是辩论动作，会逼路人选边站，而你要的是他们点头。
- 结尾落在"所以我觉得……"式的个人判断或补充事实上，不要以"请问你怎么解释"收尾。

### 长度：能短则短，不设下限
- 一句话能说清就只写一句话，几十个字完全没问题，不要为了凑长度展开。
- 上限 500 字。超出说明你写散了，删掉最弱的论据，只保留最硬的那一条。
- 宁短勿长：内容不足时，缩短篇幅比填充废话更可信。

## 输出格式
你必须以 JSON 格式输出，不要包含其他内容：
{
  "analysis": {
    "hasErrors": true,
    "errorTypes": ["factError", "logicFallacy"],
    "summary": "该回答存在事实错误和逻辑谬误，主要表现为..."
  },
  "errors": [
    {
      "type": "factError",
      "location": "回答第二段",
      "originalClaim": "原文中的错误陈述",
      "correction": "正确的信息",
      "explanation": "为什么这是错误的简要说明"
    }
  ],
  "rebuttal": "生成的反驳评论正文（可直接发布到知乎评论区）",
  "confidence": "high"
}

注意：
- confidence 只能是 "high"（确信）| "medium"（较有把握）| "low"（存疑，建议用户谨慎）
- 如果内容没有明显错误，hasErrors 设为 false，rebuttal 为空字符串；
  不要为了产出内容而把"不够全面"当成错误
- rebuttal 长度上限 500 字，不设下限：一句话能说清就一句话，几十字完全可以，
  禁止为凑长度注水
- 时间纪律：用户消息中给出了"当前日期"。凡涉及"最近、上个月、前几年、旧闻、翻旧账"
  等时效判断，必须以该日期为基准推算，禁止凭训练数据的时间印象猜测
  （例如把 2025 年的事件说成"上个月"）。算不准就删掉具体时间，改用模糊表述或省略
- 发布前自检 rebuttal：每句话必须能归入以下三类之一——
  ① 可验证的事实/数据/事件；② 个人观点或感受；③ 对原文具体内容的指认。
  若出现第四类（对作者态度、框架、讨论方式的评价），删掉重写
- 人味自检：全文不得出现"公开报道显示""数据显示""根据公开信息"等报道腔短语；
  默读一遍，想象一个普通人刷到这条评论——是否自然得像随手写的？不像就改写
```

## 3. User Prompt 设计

### 3.1 标准版本

```
请分析以下知乎回答，识别其中的错误并生成反驳评论。

## 当前日期
{当前日期，如 2026年10月8日星期四}（所有关于"新旧、最近、上个月、前几年"的时效判断，必须以此日期为基准计算）

## 回答信息
- 标题：{问题标题}
- 作者：{作者名}
- 赞同数：{赞同数}
- 链接：{URL}
- [可选] 用户特别关注的错误类型：{错误类型列表}

## 回答正文
```
{回答正文}
```

请按照系统提示词中的 JSON 格式返回分析结果。
```

### 3.2 简化版本（用于超长内容）

```
分析知乎回答并生成反驳。{重点关注错误类型}
当前日期：{当前日期}（时效判断以此为准）
标题：{标题} | 作者：{作者}
正文（已截断）：
{截断后的正文}

返回JSON格式结果。
```

### 3.3 设计要点

- **当前日期前置**：注入分析时的真实日期（北京时间），杜绝模型凭训练数据时间感误判"新旧/最近/上个月"
- **回答信息前置**：让 AI 了解上下文（标题、作者、赞同数）
- **正文用代码块包裹**：与指令部分清晰分离
- **错误类型过滤**：根据用户设置，提示 AI 重点关注特定类型
- **截断提示**：超长内容时明确告知 AI"已截断"

## 4. 动态 Prompt 调整

为提升对「原因分析 / 评价类」问题的生成深度，System Prompt 不再完全静态，而是根据回答内容特征动态拼接附加指令。

### 4.1 触发条件与附加指令

| 触发条件 | 附加指令 |
|---------|----------|
| 问题标题含「为什么/为何/原因/怎么/如何/有哪些」 | 若需补充原因，直接给出具体、可查证的事实或事件，不要写"你没考虑到…"这类对作者的评价 |
| 回答长度 < 200 字 | 若确有以偏概全或论证跳跃，用一个具体反例说明，不要用"太片面""不严谨"这类评价性措辞 |
| 回答长度 > 1500 字 | 挑出最硬的一处错误重点处理，不要在评论中逐条点评全文 |
| 检测到历史/科学/数据关键词 | 切换专家口吻，强化对应领域检查 |
| 用户开启「要求标注来源」 | 依据写入 errors 的 correction 字段；rebuttal 中提来源必须口语化（"之前新闻都报了"），禁止"公开报道显示"式报道腔 |

> 注意：动态指令的措辞会直接渗进 rebuttal。所有指令一律要求"补充事实"，
> 不得要求"指出对方遗漏"，否则会诱导模型输出元评论。

### 4.2 Few-shot 示例注入

对「论证不完整」场景注入 1–2 个简短示例。**示例的措辞就是模型的模仿对象**，
因此每个示例同时示范「正确写法（直接给事实）」和「错误写法（评价对方框架，严禁模仿）」：

```
问题：日本侵华为什么没能三个月灭亡中国？
回答：因为国民政府一直不投降。
分析：回答只给了一个原因。可补充的关键事实——1937 年淞沪会战打破日军速战预期，
     1938 年武汉会战后战争进入相持阶段；中国战略纵深极大，日军兵力不足以占领全境；
     敌后战场牵制了大量日军；国际反法西斯援助逐步到位。errorTypes 应包含 "argumentIncomplete"。

rebuttal 正确写法（直接给事实，不评价对方）：
"其实 1937 年淞沪会战打完，日军速胜的打算就落空了，1938 年武汉会战后直接进入相持阶段。
中国这么大的战略纵深，日本那点兵力根本占不下来，加上敌后战场一直牵制着，这才拖成了持久战。"

rebuttal 错误写法（严禁模仿，这是对框架的评价）：
"这回答有点跑偏了吧，只说国民政府不投降，完全没考虑战略纵深和敌后战场，太不全面了。"
```

示例按问题类型动态选择，不破坏 JSON 输出格式约束。

> 分支匹配优先级：评价类（如何评价/怎么看/有哪些）**先于**原因类（为什么/如何/怎样）。
> 否则标题含「如何」的"如何评价…"会被原因类分支错误命中。

## 5. 反馈闭环

### 5.1 反馈入口

分析面板为每个生成结果提供反馈按钮：
- 👍 有用
- 👎 漏重点
- 👎 太泛泛
- 👎 不准确
- 👎 语气差

### 5.2 反馈应用

反馈数据保存到本地历史记录。重新生成时，系统自动将最近一次负面反馈转换为 `regenerateHint`，例如：

- 「用户认为反驳太泛泛，请具体指出原文哪里有问题，并补充更关键的原因。」
- 「用户认为漏掉了重点，请优先补充被原回答忽略的核心视角。」

### 5.3 自定义 Prompt 后缀

高级用户可在设置页追加自定义规则，扩展会将其拼接到 System Prompt 末尾。

## 6. 输出格式规范

### 6.1 JSON Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["analysis", "rebuttal", "confidence"],
  "properties": {
    "analysis": {
      "type": "object",
      "required": ["hasErrors"],
      "properties": {
        "hasErrors": { "type": "boolean" },
        "errorTypes": {
          "type": "array",
          "items": {
            "enum": ["factError", "logicFallacy", "historicalNihilism", "dataFraud", "scienceError", "argumentIncomplete"]
          }
        },
        "summary": { "type": "string" }
      }
    },
    "errors": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "type": { "type": "string" },
          "location": { "type": "string" },
          "originalClaim": { "type": "string" },
          "correction": { "type": "string" },
          "explanation": { "type": "string" }
        }
      }
    },
    "rebuttal": { "type": "string" },
    "confidence": {
      "type": "string",
      "enum": ["high", "medium", "low"]
    }
  }
}
```

### 6.2 解析策略

代码实现 (`src/shared/utils.js` 中的 `extractJSON`)：
1. 先尝试匹配 ` ```json ... ``` ` 代码块
2. 再尝试直接解析整个文本
3. 解析失败时返回 null，由调用方处理

## 7. 风格差异对比

### 7.1 温和理性风格示例

**System Prompt 附加**：
```
请保持温和、理性的语气，以建设性的态度指出错误，避免攻击性语言。
```

**输出特征**：
- 使用"我认为"、"可能"等缓和措辞
- 以补充信息的方式纠正错误
- 肯定对方可能的合理出发点
- 适合：一般性讨论、对方非恶意的情况

### 7.2 直接犀利风格示例

**System Prompt 附加**：
```
请直接指出错误，语气可以较为犀利，但仍需基于事实和逻辑，避免人身攻击。
```

**输出特征**：
- 开门见山指出错误
- 使用"这是错误的"、"事实并非如此"等直接表达
- 逻辑链条清晰有力
- 适合：明显错误、可能造成较大误导的情况

### 7.3 学术严谨风格示例

**System Prompt 附加**：
```
请采用学术化的严谨语气，引用权威来源，使用专业术语，论证过程严密。
```

**输出特征**：
- 引用具体文献或数据来源
- 使用专业术语
- 论证结构严谨（论点-论据-结论）
- 适合：学术、专业领域讨论

### 7.4 自然真实风格示例

**System Prompt 附加**：
```
请像一个正在刷知乎的普通网友，随手写一条评论。语气自然、口语化，可以带一点个人情绪和主观看法，像真人之间的讨论。不要像 AI 助手在写分析报告，不要分点罗列，不要"综上所述"等套话。允许句子不完整、略带啰嗦，重点是读起来像真人写的。
```

**输出特征**：
- 口语化表达，像随手评论
- 允许个人情绪和主观看法
- 句子长短不一，可能略带啰嗦或断句
- 不刻意结构化，不罗列要点
- 适合：希望反驳内容不易被识别为 AI 生成的场景

## 8. 调优记录

### 8.1 已知挑战

| 挑战 | 现状 | 优化方向 |
|------|------|----------|
| AI 过度自信 | 有时对不确定的内容给出 high 置信度 | 在 Prompt 中强调"不确定时标注存疑" |
| 反驳过于冗长 | 超出 800 字限制 | 明确长度约束，要求简洁有力 |
| 错误定位模糊 | "回答中有错误"而不具体 | 要求指出具体段落 |
| 引用来源虚构 | AI 可能编造不存在的来源 | Prompt 要求"尽可能引用"而非强制，允许标注"据我所知" |
| 论证不完整 | AI 只纠表面错误，遗漏关键视角 | 新增「论证不完整」类型 + 动态 Prompt + Few-shot 示例 |
| **元评论高频出现** | **模型常输出"这回答有点跑偏了吧""答非所问"等对作者框架的评价，路人无法核实、观感像吵架** | **新增「读者与场景」受众定义 + 「禁止元评论」黑名单 + 开头必须给事实 + 自检三分法** |
| 论证不完整被滥用 | 模型把"不够全面"当成错误凑数 | 增加三点严格门槛，缺一即按无错误处理 |
| **靶心漂移** | **模型用事实包装后攻击作者的用词/提问（如"翻出来"），绕开核心断言** | **新增「选对靶心：反驳断言，不反驳措辞」前置步骤，先提取断言再选择攻击目标** |
| **时间感知缺失** | **模型凭训练数据时间感把旧闻说成"上个月"（如 2025 年 1 月的事件在 2026 年 10 月被说成上个月）** | **用户提示词注入当前日期（北京时间）+ 系统提示词时间纪律，禁止凭印象猜测时效** |
| **报道腔 / AI 味** | **模型输出"公开报道显示""数据显示"等来源模板，真人评论不会这样说话，一眼可辨 AI** | **「来源表达」小节：常识事实不标来源；提依据用"之前新闻都报了"式真人措辞；禁报道腔短语 + 人味自检** |

### 8.2 迭代计划

- **v1.1**：根据用户反馈优化 Prompt，增加更多错误类型子分类
- **v1.2**：引入 Few-shot 示例，提高输出一致性；新增「自然真实」风格，降低 AI 痕迹
- **v1.3**：新增「论证不完整」检测、动态 Prompt 调整、用户反馈闭环
- **v2.0**：支持用户自定义 Prompt 模板
- **v1.4（当前）**：攻克高频"元评论"问题——新增「读者与场景」受众定义、禁止元评论黑名单、
  「开头必须给事实」「少而准」取舍原则、论证不完整三点门槛、长度不设下限；Few-shot
  改为"正确写法 + 错误写法（严禁模仿）"双示范
- **v1.5（当前-2）**：修复靶心漂移 + 时间感知缺失——新增「选对靶心：反驳断言，不反驳措辞」
  前置步骤；用户提示词注入当前真实日期（北京时间），系统提示词增加时间纪律
- **v1.6（当前-3）**：修复"报道腔/AI 味"——新增「来源表达：像真人一样给依据」小节与报道腔
  短语黑名单；showSource 指令改为要求人味措辞；自检增加"人味自检"

## 9. 测试用例

### 9.1 事实错误测试

**输入**：
```
中国的首都是上海。
```

**期望输出**：
- hasErrors: true
- errorTypes: ["factError"]
- rebuttal 包含"首都是北京"的正确信息

### 9.2 逻辑谬误测试

**输入**：
```
如果不每天运动，就一定会得心脏病。我邻居从不运动，所以他迟早会得心脏病。
```

**期望输出**：
- hasErrors: true
- errorTypes: ["logicFallacy"]
- 指出滑坡论证或以偏概全的问题

### 9.3 论证不完整测试

**输入**：
```
问题：日本侵华为什么没能三个月灭亡中国？
回答：因为国民政府一直不投降。
```

**期望输出**：
- hasErrors: true
- errorTypes: 包含 "argumentIncomplete"
- 满足三点门槛：具体遗漏要素（淞沪会战/武汉会战/战略纵深/敌后战场/国际援助）
- rebuttal 直接给出可查证的事实补充，不出现"你没考虑""太不全面"等元评论

### 9.4 无明显错误测试

**输入**：
```
我认为阅读是一个很好的习惯，它可以帮助我们拓展视野、提高思维能力。
```

**期望输出**：
- hasErrors: false
- rebuttal: ""

### 9.5 元评论禁令测试

**输入**：
```
问题：如何评价某历史事件的影响？
回答：该事件加速了社会变革。
```

**期望输出**：
- rebuttal 中**不得出现**：跑偏、歪楼、答非所问、避重就轻、偷换概念、诡辩、
  没正面回答、不够全面等评价作者框架/态度的措辞
- rebuttal 不以"你"为主语的质问句开头或收尾
- rebuttal 前 30 字内包含具体的事实、数据或反例
- 未满足「论证不完整」三点门槛时，不判定为 argumentIncomplete

### 9.6 选对靶心测试

**输入**：
```
今夕是何年 名为电诈实际是人体贩卖组织，现在翻这些出来 不太懂背后意图 有人分析下吗
```

**期望输出**：
- rebuttal 围绕原文核心断言（"名为电诈实际是人体贩卖组织"的定性是否有据）展开，
  核查"电诈 vs 人口贩卖 vs 器官贩卖"的区分与证据
- rebuttal **不得**攻击原文措辞（"翻出来"）或原文的提问态度（"不太懂背后意图"）
- 不得出现"说XX有点怪""用词不准确"类表述

### 9.7 时间基准测试

**输入**（假设当前日期 2026 年 10 月 8 日）：
```
回答：王星是2025年1月在泰缅边境失联的，现在翻这些出来……
```

**期望输出**：
- rebuttal 中"上个月""最近"等时效表述必须与当前日期（2026-10-08）吻合；
  2025 年 1 月应表述为"前一年多"或"去年初"，**不得**写成"上个月"
- 若模型无法准确推算时效，允许省略具体时间，不得凭训练印象猜测

### 9.8 人味测试（报道腔禁令）

**输入**：
```
今夕是何年 名为电诈实际是人体贩卖组织，现在翻这些出来 不太懂背后意图 有人分析下吗
```

**期望输出**：
- rebuttal **不得出现**：公开报道显示、据媒体报道、数据显示、根据公开信息、
  业内人士称、相关人士透露、不难看出等报道腔/公文腔短语
- 常识级事实（妙瓦底园区是电诈窝点）直接陈述，不标注来源
- 若给依据，使用"之前新闻都报过""我记得看过报道"等真人措辞
- 整体读起来像一个普通用户随手发的评论，不以"所以 X 显示了……"之类句式收尾

## 10. 安全约束

### 10.1 禁止行为

Prompt 中明确禁止 AI：
- 进行人身攻击
- 泄露用户隐私
- 生成违法违规内容
- 冒充特定身份发表观点

### 10.2 不确定性处理

当 AI 对某条内容不确定时：
- 置信度设为 "low"
- 在 rebuttal 中标注"此处存疑"
- 不提供没有把握的具体数据
