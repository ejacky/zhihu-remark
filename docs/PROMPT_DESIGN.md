# Prompt 设计

> 现行 Prompt 的唯一说明文档。正文在 `src/shared/prompts.js`（`getSystemPrompt`），
> 这里只写**为什么这么写**和**怎么验证**，不复制正文（避免两份真源）。
> 改 Prompt 前先读第 4 节的三条教训——那三条都是付过代价的。

## 1. 两条标尺

生成的东西要同时满足：

1. **是真反驳**：打在原文的核心断言上，给出可核验的事实/条文/数字/专名，让那句话站不住；
   不是「这段不严谨」「值得商榷」这种泛评。
2. **说服对象是围观网友**：读者是刷到评论的第三方。让他点头，而不是让他觉得评论区又吵起来了。

两条经常冲突。经验：**越靠近事实越安全**——把压力放在「这件事实际是什么样」上，
比放在「你哪里错了」上，既更锋利也更不招反感。

## 2. 现行结构

| 部分 | 内容 | 为什么 |
|---|---|---|
| 三条判据 | ① 主语检验：换成「张三说」还成立 = 在说文本 ② 专名锚定：每个反驳点绑一个可核验名词，绑不上就删点 ③ 点破跳点：说出推理断在哪 | 这三条都能自检；判据比禁令好执行，也不会互相打架 |
| 结构 | 定性 ≤25 字 → 中间对账（你说的 X / 实际 Y，Y 带专名）→ 点破跳点 → 收尾落在事实 | 「对账」逼着给证据，避免写成读后感 |
| 篇幅 | 看**原文多长 + 能带专名的反驳点数**分档；一段里能说清两个点就并段；不设字数区间 | 见教训 1、2、3 |
| 纪律 | 专名拿不准就整条删点，宁可少写一段 | 写错一个专名，整条评论就废了 |

**关键分寸**：这里的数字都是「分档上限」，不是目标值。一旦写成 `2~4 段`、`250~650 字`
这种与内容无关的绝对值，模型就会当模板去凑——三句话的原文也能给你扩成四五段。

## 3. Prompt 里最容易被误删的一句

> 一段里能说清两个点就并在一段。

它看着像"排版建议"，实际是**唯一的收缩指令**。删掉它之后，模型会退化成"一个点一段"，
30 字的原文能写出 4 段。`tests/prompt/rules.test.mjs` 里有一条断言专门守着它。

## 4. 三条教训（都付过代价）

| 教训 | 怎么发现的 | 结论 |
|---|---|---|
| **约束越多，输出越保守** | 388 行 / 50 条约束 → 模型为了不违规，把论证压成一句"正确但无用"的概述；精简到 100 行后同一篇评分 1 → 4.5 | 减法比加法有效；想改语气就改**单个句式**，别堆禁令 |
| **「避免反感」不能靠加约束** | 按"读者视角"大改一版（读者定义 / 禁判卷开场 / 正反例 / 死亡规则），输出变得有气无力、像免责声明，而 L0 指标全绿 | 加约束只会让模型更谨慎；L0 全绿不等于可读 |
| **删掉收缩指令，段数就失控** | 以"读者没耐心看长段"为由删掉"并段"，30 字原文出 4 段 | 控制长度要**少写点**，不是把点揉进一段；"并段"必须留着 |
| **「评论」框架比「反驳」温和** | 2026-10-28 做了三版评论框架（v5 纯评论 / v6 加靶心 / v7 加拆段），同一批 4 篇、每格 2 次采样：输出更具体、几乎零对抗、对引用错误的抓取更准，但**锋利度明显下降** | 保留反驳框架。产品要的是"能一击中的"，不是"最不得罪人"；评论框架的不对抗优势不值得用锋利度换 |

## 5. 验证：两层，各管一半

| 层 | 判什么 | 谁判 | 在哪 |
|---|---|---|---|
| **L0** | 段数、字数、专名数、「你说的」次数、判卷开场、教训收尾、黑话 | 代码 | `tests/prompt/rules.mjs` |
| **L1** | 判卷感、有气无力、说服力 | 人，**配对盲评二选一** | 见 §6 |

**L0 只负责淘汰，不负责择优。** 第 4 轮那次改版的 L0 全绿，读起来却像免责声明——
指标测不出语气，选优必须靠人。

L1 为什么二选一而不是打分：跨轮次的 1~5 分不可比（同一篇给过 4.5、给过 1），
而「这两条哪条更好」稳定得多。

```powershell
node tests/prompt/rules.test.mjs     # 11 项断言，约 15ms，不需要 Key、不联网
```

覆盖：L0 判据本身（好样本零违规、坏样本逐条命中）、段数上限随原文长度变化、
**约束密度 ≤ 42 处且长度 ≤ 1300 字符**（防"加禁令治反感"复发）、不得出现 `2~4 段`、
必须保留「并在一段」、golden 集完整性、仓库里不得有 `.env`。

## 6. 改 Prompt 的流程

```powershell
# 1) 先跑测试，确认基线是绿的
node tests/prompt/rules.test.mjs

# 2) 哨兵：只跑最难的一篇（131 字，最容易出四五段）
node dist\b0\compare.mjs --only v3 --label 哨兵 --articles 伤痕文学

# 3) 哨兵通过再跑全量；结果在 dist\b0\out\<时间戳>\，每轮独立目录不会覆盖
node dist\b0\compare.mjs --only v3 --label 全量

# 4) 盲评：两条一对，只问一个题——哪条更可能让中立读者点头、且不觉得被冒犯
# 5) 赢了才写回 prompts.js（一个 commit）；平或输就不动基线
```

`dist/b0/` 这套跑批器不入库（依赖 Key 与网关行为，放仓库只会腐烂），需要时按上面重建。

三条铁律：

1. **必须带对照臂**。跨天比较会被"网关今天有没有触发思考""模型是否悄悄升级"污染。
2. **每格至少 2 次采样**。同一条 Prompt、同一篇文章，两次输出的字数实测能差到 **2.2 倍**（79 / 175），不是 ±15%。单次采样分不出"版本差异"和"掷骰子"。
3. **`reasoning_tokens = 0` 的样本作废重跑**。同一组参数，三次里有一次没进思考模式（8 秒出稿）。

## 7. 记录：假设表、差评库、停止条件

改 Prompt 前必须写一行假设；改完必须能回答"哪条输出让我这么改"。**没有差评样本的改动不算改动，算灵感。**

### 7.1 假设表

| 日期 | 假设 | 改了什么 | 结果 | 采纳 |
|---|---|---|---|---|
| 10-27 | 388 行 / 50 条约束让输出变保守 | 整段精简到三判据 | 同一篇评分 1 → 4.5 | ✅ |
| 10-28 | 加"读者定义 + 禁判卷 + 正反例"能减少反感 | 整段重写 | 有气无力，像免责声明 | ❌ |
| 10-28 | 删掉"并段"能让段落更短 | 删一条 | 30 字原文出 4 段 | ❌ |
| 10-28 | 评论框架更不招反感 | 整段换（v5/v6/v7 三版） | 更具体但太温和，不如反驳版 | ❌ |
| 10-28 | 靶心能治"只补边角" | 加 1 条 | 70 年代题回到主线 | ⚠️ 部分 |
| 10-28 | 三个已知瑕疵一起修（拆长段/禁"跳点"/「你说的」≤2） | v8，5 篇 ×2 次 | 盲评 2:2 平；「你说的」1.6→0.8 但读者无感；拆长段反而更长 | ❌ |

改之前先查这张表——"加约束治反感"已经试过两次了。

### 7.5 复盘（2026-10-28，两天 8 版）

- **有效 4 条**：去掉 JSON（一次改动值 2 分）、预算提到 16384（消除截断）、388 行 → 700 字符（约束密度降下来才有话说）、保留「并段」（唯一的收缩指令）
- **无效 5 条**：加约束治反感、评论框架三版、`100~200 字` 硬区间、`段数上限 = 点数 + 1`、拆长段（锚点选了个正被消灭的短语）
- **两条反直觉教训**：① L0 全绿不等于可读（两次踩坑）；② 指标改善不等于读者感知（「你说的」腰斩，盲评 2:2）
- **耗时主因**：改动靠灵感、单次采样、盲评没有版本映射、没有停止条件——前三条已修（badcases / `--repeat 2` / 仍待修映射）
- **冻结依据**：连续两轮 A/B 无胜出（评论框架 0 胜、v8 打平）。剩余问题（靶心选择、漏原文细节）更像**输入侧**问题，继续改措辞预计仍是打平
- **下一轮如果重启调优**：一次只改一句、每格 2 次采样、跑 blind-sheet 前先确认 `blind-key.json` 已生成

### 7.2 差评库

`tests/prompt/badcases/`，每条一个文件：原文引用 + 输出全文 + 一句话归因 + 期望。已有三条：

- `2026-10-28-长段` —— 一段塞三个对账句（183 字）
- `2026-10-28-黑话与整篇判决` —— "跳点"漏进正文 / 首句判决整篇
- `2026-10-28-评论框架太温和` —— 事实都对但不动人（方向性反例）

作用不是测试，是**防止重犯**：谁想再改这几处，先看它为什么被否。

### 7.3 盲评页

```powershell
node tests/prompt/blind-sheet.mjs --run "dist/b0/out/<本轮目录>" --a v6 --b v7
# 生成 <本轮目录>/blind.md：左右随机、隐藏版本名，每题只问"哪条更让中立读者点头且不冒犯"
# 加 --samples 2 会每篇出两题（更适合看稳定性，但题量翻倍）
```

人工成本要压到**5 分钟 4 道二选一**，否则这套机制活不过三周。

### 7.4 停止条件

**连续两轮 A/B 无胜出 → 冻结 Prompt，转去做别的（B3 等）。**

这条比上面任何一条都重要：没有停止条件就会无限调优。我们已经在这上面花了十几轮。

## 9. 不做的事

- **不让模型自己改 Prompt**：试过一次，它只会加约束，而加约束的代价是输出变谨慎。让模型做**归因**可以（"这条为什么不行"它答得很准），做**改法**不行。
- **不引入 npm / vitest / esbuild**：`node --test` 够用，零工具链是资产。
- **不在文档里复制 Prompt 全文**：正文只有 `prompts.js` 一份。
