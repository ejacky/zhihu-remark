# 计划：无错误时支持重新分析 + 产品讨论记录

## 讨论背景

用户提问：当 AI 返回"未检测到明显错误"时，是否应该在面板中提供"重新生成/重新分析"按钮？用户的观察是：同样的内容，模型不同次调用的判定可能有方差，重新分析可能得到不同结论（从无错误变为有错误）。

## 产品分析：这是否是伪需求？

### 结论：不是伪需求，但需要以正确的方式实现

**支持实现的理由：**

1. **LLM 判定的固有方差**
   - 当前 temperature=0.7，对于 borderline 内容（有争议但不明显的错误），不同次调用的 `hasErrors` 判定确实可能不同
   - 特别是 prompt 中要求"如果不确定某个内容是否错误，标注'此处存疑'而非武断否定"，这种模糊策略增加了方差

2. **当前体验是死胡同**
   - 无错误时面板只有一个关闭按钮，用户没有其他操作路径
   - 如果用户**主观上认为**回答有错但 AI 没检测出来，会感到挫败

3. **产品定位一致性**
   - 本工具的定位是"AI 辅助"，最终判断权在用户
   - 既然有错误时给了"重新生成"，无错误时给"重新分析"保持了交互一致性

**需要注意的风险：**

1. **API 费用浪费** — 如果内容确实没有错误，反复分析是浪费 token
2. **刷结果心理** — 用户可能陷入"刷到 AI 说有错误为止"的循环
3. **降低可信度** — 如果第一次说没错、第二次说有错，用户会对 AI 判定产生不信任

### 推荐方案：温和重试

不在无错误面板中直接显示"重新生成反驳"（因为此时还没有反驳可生成），而是显示一个次要的"🔄 再次检测"按钮，并辅以提示文案：

```
AI 未在该回答中发现明显的事实错误或逻辑谬误。
（AI 判定可能存在方差，如对内容有疑问可再次检测。）
                              [🔄 再次检测]
```

这样：
- 给用户一个非死胡同的出路
- 文案暗示这是"检测"而非"生成"，管理预期
- 按钮为次要样式，不喧宾夺主
- 如果再次检测仍无错误，面板保持不变，用户可继续点击或关闭

## 实施方案

### 改动文件

| 文件 | 改动 |
|------|------|
| `src/content/ui.js` | `createAnalysisPanel` 的无错误分支中增加"再次检测"按钮 |
| `src/content/injector.js` | `onRetry` 回调支持无错误时重新触发分析 |
| `src/content/index.js` | `injectStyles()` 中无错误区域增加提示文案样式 |
| `src/content/style.css` | 同步 |

### 详细设计

**UI.createAnalysisPanel 无错误分支：**

当前：
```
AI 未在该回答中发现明显的事实错误或逻辑谬误。
```

改为：
```
AI 未在该回答中发现明显的事实错误或逻辑谬误。
（AI 判定可能存在方差，如对内容有疑问可再次检测。）
                              [🔄 再次检测]
```

- "再次检测"按钮点击后：当前风格标记为 loading → 触发 API → 更新面板
- 如果再次检测后有错误，面板自动切换到"有错误"的完整布局（标签+摘要+反驳预览+操作按钮）
- 如果再次检测后仍无错误，保持无错误提示，按钮恢复可用

**injector.js 回调处理：**

`_openAnalysisPanel` 中的 `onRegenerate` 已经支持按风格重新生成，无错误时的"再次检测"本质上就是对该风格调用 `generateForStyle(style, true)`（带重新生成提示），因此：

- 无错误面板添加 `onRetry` 回调，内部调用 `generateForStyle(currentStyle, true)`
- `generateForStyle` 完成后，面板 `update()` 会自动根据新的 `hasErrors` 状态切换布局

### 验收标准

- [ ] 无错误时面板底部显示"再次检测"按钮（次要样式）
- [ ] 点击"再次检测"后按钮进入 loading 状态，显示"正在重新分析..."
- [ ] 重新分析后有错误时，面板完整展示错误标签、摘要、反驳预览和操作按钮
- [ ] 重新分析后仍无错误时，恢复"再次检测"按钮可用状态
- [ ] 各风格独立：在风格 A 下点击"再次检测"不影响风格 B/C 的数据
